# Internationalization (i18n)

A complete, production-ready internationalization system for the Amazon AI
Commerce Platform. It supports **English** and **Simplified Chinese (zh-CN)** out
of the box, lets **every page switch language instantly without a refresh**, and
persists the choice to the **browser**, the **database** and the **user profile**.

## The persistence contract

When a user switches language, the choice is saved everywhere so it survives
across requests, devices and sessions:

| Backend | How | Enabled by |
|---------|-----|-----------|
| **Browser** | a `lang` cookie is set on the response | `POST /i18n/switch` |
| **Database** | a row is upserted in `i18n_language_preferences` (unique per user+device) | `persist_to_db` |
| **User profile** | written into `UserSettings.display_preferences.i18n.language` | `persist_to_user_profile` |
| **API requests** | any request resolves via `?lang=`, the `lang` cookie, or `Accept-Language` | per-request resolution |

### Language resolution priority

```
query param (?lang=zh-CN)  >  cookie (lang)  >  Accept-Language header  >  stored preference  >  default (en)
```

Resolution is handled by `LanguageSwitcher.resolve()` and exposed via
`GET /i18n/current`.

## What is and isn't translated

| Translated | NOT translated (stays English) |
|------------|-------------------------------|
| UI text, buttons, menus, titles | System logs |
| Validation messages, errors | Database field names |
| Notifications, tooltips | API field names |
| Charts, tables, emails | — |
| PDF reports, CSV exports | — |
| AI responses (assistant replies in the selected language) | — |

Only **displayed content** is translated — the `t()` function and the locale
formatters are used purely at the presentation boundary.

## Supported formatting

`LocaleManager` provides locale-aware, pure-stdlib formatting:

- **Pluralization** — per-language rules (`en`: one/other; `zh-CN`: no inflection).
  `pluralize(5, "item")` → `5 items` (en) / `5 item` (zh-CN).
- **Dates & times** — locale format strings + timezone conversion via `zoneinfo`.
  `format_date(now)` → `2026年08月12日` (zh-CN) / `2026-08-12` (en).
- **Numbers** — grouping + decimal separators. `format_number(1234567.89)` → `1,234,567.89`.
- **Currency** — locale symbol/position. `format_currency(1234.5)` → `¥1,234.50` (zh-CN) / `$1,234.50` (en).
- **Timezone** — convert any datetime to the locale's default timezone.

Every locale's formatting is demonstrated live via
`GET /i18n/locale/{language}`.

## Translation storage

Translations live under `translations/<language>/<module>.{json,yaml}`:

```
translations/
  en/
    common.json  dashboard.json  products.json  analytics.json
    settings.json  agent.json  assistant.json
  zh-CN/
    common.json  dashboard.json  products.json  analytics.json
    settings.json  agent.json  assistant.json
```

Both **JSON** and **YAML** are supported (the loader and validator read
`.json` / `.yaml` / `.yml`). Keys use dot-notation, e.g. `dashboard.title`, with
`{placeholder}` interpolation, e.g. `common.pagination.page` → `Page {page}`.

**Adding a new language requires no application code changes** — drop a new
directory under `translations/` (e.g. `de/`) with the same modules/keys, and add
the code to `I18nConfig.supported_languages`. Everything — loader, service,
switcher, validator — picks it up automatically.

## Lazy loading & caching

- **Only the current language is loaded.** Modules are read from disk on first
  use (`TranslationLoader`) and cached in memory.
- **Redis cache** (`TranslationCache`, prefix `i18n:`) with a configurable TTL
  for production; falls back to an in-memory dict when Redis is unavailable.
- `GET /i18n/bundle?language=zh-CN` returns the full bundle for the current
  language — the frontend fetches this once per language switch and re-renders
  **without a page refresh**.
- `POST /i18n/reload` drops caches and re-reads translation files from disk.

## Validation

`TranslationValidator` guarantees **every translation key exists in every
language** and reports:

- **missing translations** — a key present in some languages but not others;
- **unused translations** — a key in one language but not the reference
  language, plus a code-usage scan that reports defined keys never referenced in
  the application source (`scan_code_usage`);
- **duplicate keys** — the same key defined twice in a single file (detected via
  a JSON `object_pairs_hook` / a duplicate-aware YAML loader);
- **module mismatches** — a module present in some languages but not others.

`POST /i18n/validate` returns structured findings for CI/CD:
`is_valid`, `missing_keys`, `unused_keys`, `duplicate_keys`,
`module_mismatches`, `code_usage` and a human-readable `summary`.

## Components

| Component | Responsibility |
|-----------|----------------|
| `TranslationLoader` | discovers languages/modules, loads JSON/YAML lazily |
| `TranslationCache` | Redis-backed cache with local fallback + TTL |
| `TranslationService` | `t(key, **vars)` translation, interpolation, fallback, `translate_dict` |
| `LocaleManager` | date / number / currency / timezone / pluralization formatting |
| `LanguageProvider` | request-scoped language + `TranslationService` injection |
| `LanguageSwitcher` | resolve + switch + persist to browser / DB / profile |
| `TranslationValidator` | missing / unused / duplicate keys, module mismatches, code usage |
| `I18nManager` | facade for the whole subsystem |
| `I18nConfig` | defaults, supported languages, persistence + cache settings |

## API surface

| Endpoint | Purpose |
|----------|---------|
| `GET /i18n/capabilities` | supported languages, modules, plural rules, currencies |
| `GET /i18n/languages` | list languages with display/native names |
| `GET /i18n/current` | resolve the current language for this request |
| `POST /i18n/switch?language=zh-CN` | switch language; persist to cookie + DB + profile |
| `GET /i18n/preference?user_id=` | stored preference for a user/device |
| `GET /i18n/bundle?language=` | full bundle for a language (lazy-loaded) |
| `GET /i18n/translations/{module}` | a single module's translations |
| `GET /i18n/locale/{language}` | exemplar formatting (date/number/currency/tz/plural) |
| `POST /i18n/validate` | report missing / unused / duplicate keys |
| `POST /i18n/reload` | drop caches, reload translation files |
| `GET /i18n/stats` | platform aggregates |

## Quick start

```bash
# List languages
curl .../api/v1/i18n/languages

# Switch to Simplified Chinese (sets the lang cookie; persists to DB/profile)
curl -X POST ".../api/v1/i18n/switch?language=zh-CN"

# Resolve the current language (query > cookie > header > stored > default)
curl ".../api/v1/i18n/current?lang=zh-CN"

# Fetch the full zh-CN bundle (frontend re-renders instantly, no refresh)
curl ".../api/v1/i18n/bundle?language=zh-CN"

# Locale formatting examples for zh-CN
curl .../api/v1/i18n/locale/zh-CN

# Validate translation completeness (CI gate)
curl -X POST .../api/v1/i18n/validate
```

## Usage in application code

```python
from app.core.dependencies import get_i18n_manager

async def handler(i18n: I18nManager = Depends(get_i18n_manager)):
    title = i18n.translate("zh-CN", "dashboard.title")   # 智能选品仪表盘
    page  = i18n.translate("zh-CN", "common.pagination.page", page=3)  # 第3页
    fmt   = i18n.format("zh-CN")                          # locale formatting
    bundle = await i18n.get_bundle("zh-CN")               # full bundle
```

## Production readiness

- Pure-stdlib formatting + translation (no runtime dependencies).
- Postgres persistence: `i18n_language_preferences` (migration `0016_i18n`,
  single head) — upsert, never violates the (user, device) unique constraint.
- JSON **and** YAML translation files; lazy loading; Redis caching with TTL.
- Validator enforces key parity across languages for CI/CD.
- New languages added by directory + config — zero code changes.
